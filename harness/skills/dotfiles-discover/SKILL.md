# dotfiles-discover

> **Sanitized, illustrative sample.** One engineer's convention for stopping a
> dotfiles repo from swallowing secrets, installer-owned bundles, and runtime
> state. Not a framework, policy, or best-practice claim. The chezmoi
> subcommands, config keys, and flags below were checked against chezmoi
> v2.71.1 — verify them against the version you actually run before installing,
> and note that the repo-relative links stop resolving once this directory is
> copied out.

Surface files that *should* be tracked by chezmoi without pulling in secrets,
runtime state, or installer-owned bundles. This skill owns the **canonical
secret scan** and **file-classification rules** that
[`dotfiles-sync`](../dotfiles-sync/SKILL.md) also reuses.

## Responsibility

One job: produce a *categorized, vetted* list of track candidates. It does not
add, commit, or push. Handoff: you pick the candidates → `chezmoi add <target>`
→ [`dotfiles-sync`](../dotfiles-sync/SKILL.md) to commit and push.

## Workflow

### 1. Orient — derive the roots to scan

Do not scan all of `$HOME` (huge, noisy). Scan only under directories chezmoi
already manages:

```bash
chezmoi source-path
# whichever top-level dirs your repo already tracks
roots=$(chezmoi managed | awk -F/ '{print $1}' | sort -u)
echo "$roots"
```

### 2. List unmanaged candidates, scoped

```bash
for r in $roots; do
  echo "--- ~/$r ---"
  chezmoi unmanaged "$HOME/$r" 2>/dev/null
done
```

### 3. Classify every candidate

Apply in order; first match wins:

| Class | Signals | Action |
|-------|---------|--------|
| **NEVER — secret** | filename `auth.json`, `secrets.env`, `*.pem`, `*.key`, `credentials`, `.netrc`, `hosts.yml` (gh token); or fails the secret scan below | Reject. Never recommend. |
| **NEVER — runtime/state** | `sessions/`, `logs/`, `log/`, `cache/`, `*.sqlite*`, `history.jsonl`, `projects/`, `plans/`, `tasks/`, `telemetry/`, `shell-snapshots/`, `*.marker`, `.last-*` | Reject. Regenerated by tools. |
| **NEVER — backup** | `*.bak`, `*.bak-*`, `*.backup.*`, `*.old`, `*.old.*` | Reject. |
| **CAUTION — machine-local** | filename ends `.local` (e.g. `zshrc.local`) | Read the file header first. `.local` is the deliberate untracked escape hatch; recommend ONLY if the content is clearly portable and the header does not say "local-only". |
| **CAUTION — installed bundle** | dir contains `install.sh`/`uninstall.sh`, `LICENSE`, a `config.yaml.example` template, `.system` marker, or a `config.yaml` that differs from its `.example` | Do not track — an installer owns it. If you insist, track only the non-secret template files, never the live `config.yaml`. |
| **CANDIDATE** | hand-authored config with no secrets: rules files, small tool configs, shell fragments you edited | Recommend. |

Installed-vs-authored check:

```bash
# customized config => likely holds machine/account state
diff -q "$dir/config.yaml" "$dir/config.yaml.example" 2>/dev/null \
  && echo "untouched template" || echo "customized — inspect before tracking"
```

The installed-bundle row is the one that earns its keep. A tool that ships an
installer expects to own its own config directory; tracking that directory means
your dotfiles repo and the installer both think they are the source of truth,
and you find out which one wins at the least convenient moment.

### 4. Canonical secret scan — chezmoi's built-in gitleaks

The authoritative gate is chezmoi's own gitleaks scan, not a grep. **This
assumes you have set `add.secrets = error` in your chezmoi config** — the
shipped default is `warning`, which prints and proceeds. Set it to `error`
before relying on any of this, so that a `chezmoi add` / `chezmoi re-add` which
detects a secret **exits non-zero and refuses to add the file**. A grep is not
enough; a maintained scanner recognizes credential shapes a hand-rolled pattern
does not.

Rules:

- **A detection is a HARD STOP.** Exclude the file, say which line and rule
  fired (redact the value), do not commit. **Never** pass `--secrets=ignore` to
  force a flagged file through.
- **Verified false positive only** (a human confirms it is not a secret — e.g. a
  GPG *fingerprint* in `~/.gitconfig`): exempt that single line with an inline
  `# gitleaks:allow` comment, then confirm the tool still parses the file
  (`git config --file <f> <key>`). Never lower `add.secrets` to silence it.

That last check matters more than it looks: an allowlist comment is inserted
into a real config file, and a comment syntax the owning tool does not accept
turns a false-positive fix into a broken config.

Optional fast pre-filter (weak heuristic, NOT a substitute for the gate above):

```bash
grep -InE -e 'password|passphrase|secret|token|api[_-]?key' \
          -e 'private[_-]?key|credential|BEGIN [A-Z ]*PRIVATE KEY' "$1"
```

### 5. Report

Emit a table: `Track` / `Caution` / `Never`, each row with a one-line reason.
Then ask which `Track` rows to add. On confirmation, run `chezmoi add <target>`
for each, and hand off to [`dotfiles-sync`](../dotfiles-sync/SKILL.md) to commit
and push.

## Guardrails

- **Recommend-only.** Never `chezmoi add` without explicit per-file
  confirmation.
- **Secrets are terminal.** A secret-scan hit is never overridable "just this
  once".
- **Escape hatch:** if the roots can't be derived or chezmoi isn't installed,
  stop and say so — do not fall back to scanning `$HOME`.
- Does NOT commit or push — that is
  [`dotfiles-sync`](../dotfiles-sync/SKILL.md).
